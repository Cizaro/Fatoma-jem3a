First, the big idea

What a function is

A function is a machine. You put something in, it gives something out.

A blender: put fruit in → get juice out. You do not rebuild the blender every time you want juice. You built it once, and now you use it whenever you like.

Why bother? Look at the difference

$r = 5;
echo 3.14159 * $r * $r;

$r = 7;
echo 3.14159 * $r * $r;

$r = 2;
echo 3.14159 * $r * $r;
Without a function. The same sum copied three times. If the formula is wrong, you have to fix it in three places — and you will forget one.
function area($r) {
    return 3.14159 * $r * $r;
}

echo area(5);
echo area(7);
echo area(2);
With a function. The sum is written once. Fix it there and all three are fixed. And the code now reads like English: area of 5.

How to turn any solution into a function — 3 steps

1
Find the thing that changes In the sum above, only the radius changes. So the radius becomes the parameter — the empty slot: function area($r)
2
Wrap the working lines in the box Put function name($slot) { above them and } below them. The lines themselves do not change at all.
3
Swap the last echo for return echo prints it and it is gone. return hands it back so you can store it, add it, or print it outside.
The one mistake everybody makes. Using echo inside the function instead of return.

With echo, the number appears on screen and then disappears — so area(3) + area(4) adds up nothing. With return the number comes back to you and the sum works.

Say it like this: echo = shout it out of the window. return = hand it to me.
Problem 2

integerPower (base, exponent)

The task. Write a function integerPower(base, exponent) that returns baseexponent. For example integerPower(3, 4) = 3*3*3*3. The function must use a for or while loop. Put it in a script that reads the two numbers from an HTML5 form with two text fields and a button.

Expected: 2 raised to the power 10 is 1024

The lecturer's answer, as he wrote it

<form action="Power.php" method="POST">
<label>Base </label>     <input type="number" name="B">
<label>Exponent </label> <input type="number" name="E">
<input type="submit" name="Cal" value="Calculate">
</form>
<?php
function PowerInteger($a, $n) {
    $P = 1;
    if ($n >= 0) {
        for ($i = 0; $i < $n; $i++) {
            $P = $P * $a;
        }
    }
    else {
        for ($i = $n; $i < 0; $i++) {
            $P = $P * (1/$a);
        }
    }
    return $P;
}
$Base   = $_POST["B"];
$Exp    = $_POST['E'];
$Result = PowerInteger($Base, $Exp);
echo "Result : {$Result}";
?>

Now the arrows

<form action="Power.php"
      method="POST">
We did this because the form has to send its two numbers somewhere. action names the file that receives them — here the same file, so one file holds both the form and the calculation. POST sends them hidden instead of in the address bar.
<input type="number" name="B">
<input type="number" name="E">
We did this because name is the only part PHP ever sees. name="B" is what makes $_POST["B"] exist later. Change the name here and you must change it there too — or the data vanishes.
function PowerInteger($a, $n) {
We did this because the question says to write a function. $a and $n are empty slots — they hold nothing yet. They get filled at the bottom of the file, when the function is actually called.
$P = 1;
We did this because $P is about to be multiplied over and over. Start it at 0 and every answer is 0, because 0 × anything = 0. Starting at 1 is safe — multiplying by 1 changes nothing.

The rule: adding up → start at 0. Multiplying up → start at 1.
if ($n >= 0) {
We did this because a negative exponent means something different (2-3 is a fraction, not a big number). So the code splits into two paths. The question never asked for this — it is extra credit.
for ($i = 0; $i < $n; $i++) {
    $P = $P * $a;
}
We did this because this is the whole calculation. $i < $n (not <=) makes the body run exactly n times — for n=10 it checks 0<10 … 9<10, then 10<10 fails and it stops.

Note: $i never appears in the maths. It only counts the rounds.
for ($i = $n; $i < 0; $i++) {
    $P = $P * (1/$a);
}
We did this because for a negative exponent we multiply by 1/$a instead. Starting $i at $n (a negative number) and counting up to 0 runs the loop |n| times. For 2-3 it runs 3 times and gives 0.125, which is 1/8. Correct.
return $P;
We did this because return hands the number back so it can be stored and reused. If he had written echo $P; here the number would print and then be gone — the line $Result = PowerInteger(...) would get nothing.

return also ends the function immediately.
$Base   = $_POST["B"];
$Exp    = $_POST['E'];
We did this because this is where the typed numbers arrive. The "B" and 'E' match the name= in the form exactly. Single or double quotes make no difference here.
$Result = PowerInteger($Base, $Exp);
We did this because writing a function runs nothing. This is the line that calls it. $Base goes into the slot $a, and $Exp goes into $n — in that order.
echo "Result : {$Result}";
We did this because the answer has to appear on the page. The { } around the variable is just a tidy way of putting it inside a string — "Result : $Result" does exactly the same thing.

Pseudocode

Algorithm IntegerPower
[returns BASE raised to the power EXPONENT]

    Input BASE, EXPONENT

    P <-- 1
    I <-- 0

    while (I < EXPONENT)
        P <-- P * BASE
        I <-- I + 1
    endwhile

    Print BASE, " raised to the power ", EXPONENT, " is ", P

End

Problem 1 — the unsolved one

The quadratic solver

The task. Ask the user for two coefficients and one constant of a quadratic function through three input fields, then print whether it has one solution, two solutions or no solution — and show them.

The form on the slide reads: [ ] X² + [ ] X + [ ] = 0 with a Solve it button.
The whole problem is one number. It is called the discriminant: D = b² − 4ac. Its sign tells you how many solutions exist — which is exactly the three cases the question asks about. Work out D once, then one if / elseif / else on it.
DMeaningFormula to print
> 0two solutions(−b ± √D) / 2a
= 0one solution−b / 2a
< 0no solutionyou cannot square-root a negative

The code, written in his style

<form action="Quadratic.php" method="POST">
<label>Enter the integer numbers on the following equation:</label><br>
<input type="number" name="A"> X<sup>2</sup> +
<input type="number" name="B"> X +
<input type="number" name="C"> = 0 <br>
<input type="submit" name="Solve" value="Solve it">
</form>
<?php
$a = $_POST["A"];
$b = $_POST["B"];
$c = $_POST["C"];

$D = $b*$b - 4*$a*$c;

if ($D > 0) {
    $x1 = (-$b + sqrt($D)) / (2*$a);
    $x2 = (-$b - sqrt($D)) / (2*$a);
    echo "Two solutions : X1 = {$x1} and X2 = {$x2}";
}
elseif ($D == 0) {
    $x = -$b / (2*$a);
    echo "One solution : X = {$x}";
}
else {
    echo "No solution";
}
?>

The arrows

$D = $b*$b - 4*$a*$c;
We did this because everything depends on this one number, so we calculate it once and then just ask about its sign three times. Calculating it inside each branch would repeat the same work.
if ($D > 0) { ... }
elseif ($D == 0) { ... }
else { ... }
We did this because the question literally lists three outcomes, and a number can only be positive, zero or negative. The three branches are the three cases — nothing is missing and nothing overlaps.
sqrt($D)
We did this because PHP already has a square root — the same idea as pi(). Never work one out by hand.

And notice: it is only ever used inside the D > 0 branch, where D is guaranteed positive.
(2*$a)
We did this because the brackets force the whole bottom of the fraction to be worked out first. Without them PHP would divide by 2 and then multiply by a, which is a different sum entirely.

Pseudocode

Algorithm QuadraticSolver
[finds how many solutions a quadratic has, and what they are]

    Input A, B, C

    D <-- B*B - 4*A*C

    if (D > 0) then
        X1 <-- (-B + squareroot(D)) / (2*A)
        X2 <-- (-B - squareroot(D)) / (2*A)
        Print "Two solutions : ", X1, " and ", X2
    else
        if (D = 0) then
            X <-- -B / (2*A)
            Print "One solution : ", X
        else
            Print "No solution"
        endif
    endif

End

Flowchart

Two diamonds, three ways out — and all three rejoin before Stop. That is what the question means by "one solution, two solutions or no solution".

Tested in real PHP

The trap. If she types a = 0 it is not a quadratic at all, and 2*$a becomes zero — a division-by-zero error. His style has no guards anywhere, so leave it out unless asked. If you want the extra mark, one line at the top does it:
if ($a == 0) { echo "Not a quadratic equation"; }
Problem IV

Smart-home smart plug

The task. Read one integer — the day of the month. Use the modulus operator to decide odd or even, and print a status message:

Day 14 is EVEN: Extra power mode active!
Day 15 is ODD: Eco-conservation mode active!
What % really means: what is left over after dividing.

14 ÷ 2 = 7 remainder 0  →  14 % 2 = 0  →  EVEN
15 ÷ 2 = 7 remainder 1  →  15 % 2 = 1  →  ODD

So % 2 == 0 is just asking "did it divide cleanly?"

The simplest version that answers the question

<form method="post">
    <input type="text" name="day">
    <button type="submit">Check</button>
</form>

<?php
if (isset($_POST["day"])) {
    $day = $_POST["day"];

    if ($day % 2 == 0) {
        echo "Day $day is EVEN: Extra power mode active!";
    } else {
        echo "Day $day is ODD: Eco-conservation mode active!";
    }
}
?>
if (isset($_POST["day"])) {
We did this because on the very first visit nobody has typed anything yet. Without this check PHP complains about a missing key before the page has even been used.
if ($day % 2 == 0) {
We did this because this is the entire problem. One operator, one comparison. % gives the remainder, and a remainder of zero means even.

Careful: == asks a question. A single = would put a value in and the if would behave very strangely.

Pseudocode

Algorithm SmartPlug
[decides the power mode from the day of the month]

    Input DAY

    if (DAY % 2 = 0) then
        Print "Day ", DAY, " is EVEN: Extra power mode active!"
    else
        Print "Day ", DAY, " is ODD: Eco-conservation mode active!"
    endif

End

Flowchart

Note the two branches rejoin before Stop — markers like that, because it shows you saw that both paths end the same way. Ovals top and bottom, nothing left dangling.

PHP Exercises — Set I

The circle calculator

The task. Enter a radius. Calculate the area, circumference or volume. Show the formula used and the result. The form needs a radius box, a Calculate button and a Clear button — and the PHP must work out which button was pressed.

pi() is predefined in PHP.
The real question is the two buttons. A submit button is only sent to PHP if it was the one clicked. Give them different names and isset() tells you which:

if (isset($_POST["clear"])) { ... }
elseif (isset($_POST["calculate"])) { ... }

The three formulas

$result = pi() * $r * $r;                   // Area          = π × r²
$result = 2 * pi() * $r;                    // Circumference = 2 × π × r
$result = (4 / 3) * pi() * $r * $r * $r;    // Volume        = 4/3 × π × r³
<button name="calculate">Calculate</button>
<button name="clear">Clear</button>
We did this because two different names is what makes the two buttons tellable apart. Only the clicked one is sent, so only its key exists in $_POST.
pi()
We did this because the sheet says so, and because typing 3.14 loses accuracy — and a mark. pi() is far more precise.
(4 / 3) * pi() * $r * $r * $r
We did this because the brackets say what we meant. Writing 1.33 instead of 4 / 3 makes the volume wrong in the third digit. Keep it as a division.

Pseudocode

Algorithm CircleCalculator
[reads a radius and a chosen calculation, prints the formula and the result]

    Input RADIUS, CHOICE, BUTTON

    if (BUTTON = "Clear") then
        RADIUS <-- empty
        RESULT <-- empty
    else
        if (RADIUS is not a number) OR (RADIUS <= 0) then
            Print "Please enter a positive number"
        else
            if (CHOICE = "Area") then
                RESULT  <-- PI * RADIUS * RADIUS
                FORMULA <-- "Area = pi x r^2"
            else
                if (CHOICE = "Circumference") then
                    RESULT  <-- 2 * PI * RADIUS
                    FORMULA <-- "Circumference = 2 x pi x r"
                else
                    RESULT  <-- (4 / 3) * PI * RADIUS * RADIUS * RADIUS
                    FORMULA <-- "Volume = 4/3 x pi x r^3"
                endif
            endif
            Print "Shape: Circle"
            Print "Radius: ", RADIUS
            Print FORMULA, " = ", RESULT
        endif
    endif

End
Two marks people lose in pseudocode.
  • <-- puts a value in, a single = compares. In PHP they swap round. Write the arrow on paper.
  • Three ifs need three endifs. Count them before handing in.
