The one-line version

A function saves you repeating the same work. An array saves you repeating the same variable. They solve the same disease in two different places, and they are taught next to each other for that reason.

Lesson 4

Why functions?

The lecturer's version: "We write our own functions when our code reaches a certain level of complexity." Here is what that means with a real cost attached.

Explained the simple way — a recipe card

Imagine you teach somebody to make tea. The first time, you explain all of it: boil the water, put the bag in, wait, add sugar.

Now you write those steps on a card and put the card on the wall. From then on you never explain again. You just say "make tea".

That card is a function. makeTea() is you saying its name.

And here is the part that matters: if the sugar changes from two spoons to one, you change the card. Everybody who makes tea from that moment on uses the new way, and you did not have to find every person you ever taught.

The real use case — three students, one grade rule

Three students. One rule for turning a mark into a letter.

Without a function

The rule is copied once per student:

$rana = 17; $sara = 11; $lina = 11;

if($rana >= 18){ $g = "A"; } else if($rana >= 16){ $g = "B"; }
else if($rana >= 14){ $g = "C"; } else if($rana >= 10){ $g = "D"; } else { $g = "F"; }
echo "Rana : ".$rana." grade ".$g."\n";

if($sara >= 18){ $g = "A"; } else if($sara >= 16){ $g = "B"; }
else if($sara >= 14){ $g = "C"; } else if($sara >= 10){ $g = "D"; } else { $g = "F"; }
echo "Sara : ".$sara." grade ".$g."\n";

if($lina >= 18){ $g = "A"; } else if($lina >= 16){ $g = "B"; }
else if($lina >= 14){ $g = "C"; } else if($lina >= 10){ $g = "D"; } else { $g = "F"; }
echo "Lina : ".$lina." grade ".$g."\n";

With a function

The rule is written once:

function letterGrade($mark){
    if($mark >= 18){ return "A"; }
    if($mark >= 16){ return "B"; }
    if($mark >= 14){ return "C"; }
    if($mark >= 10){ return "D"; }
    return "F";
}

$rana = 17; $sara = 11; $lina = 11;
echo "Rana : ".$rana." grade ".letterGrade($rana)."\n";
echo "Sara : ".$sara." grade ".letterGrade($sara)."\n";
echo "Lina : ".$lina." grade ".letterGrade($lina)."\n";
Both print 
Rana : 17 grade B
Sara : 11 grade D
Lina : 11 grade D

So far the function has bought nothing. It is even a line longer. Be honest about that — it is why the lecturer says "a certain level of complexity" and not "always".

Now the university raises the pass mark from 10 to 12

With the function you change one character on one line. Done.

Without it you must find all three copies. Change two and miss the third — which is what happens at one in the morning — and the page prints this:

Rana : 17 grade B
Sara : 11 grade F
Lina : 11 grade D

Sara and Lina both scored 11. Sara gets an F and Lina gets a D. The same mark, two different grades, on the same page — and nothing crashed to tell you.

That is the argument. Not that functions are shorter, because with three students they are not. It is that a rule written once cannot disagree with itself.

The lecturer's four rules

  • Organise your code into "paragraphs" — capture a complete thought and name it.
  • Don't repeat yourself — make it work once and then reuse it.
  • If something gets too long or complex, break it into chunks and put those chunks in functions.
  • Make a library of the common things you do over and over.
Lesson 5

Why arrays?

His slide asks it directly: "What problems do arrays solve in programming?" This is his own example, with what goes wrong spelled out.

Explained the simple way — an egg box

You buy six eggs. They do not come as six separate things you have to name — egg one, egg two, egg three… They come in one box with six numbered cups.

The box has one name. Each cup has a number. $eggs[0] is the first cup, $eggs[5] is the last.

And because the cups are in a row, you can walk along them — check every cup without knowing in advance what is in any of them. That walk is the loop, and it is the thing six separate variables can never give you.

An associative array is a school bag instead of an egg box. The pockets are not numbered, they are labelled: "pencils", "lunch", "keys". You ask for what you want by name, not by position.

His own example

Without an array

$days1 = "Monday";
$days2 = "Tuesday";
$days3 = "Wednesday";
echo $days1;
echo "<br>".$days2;
echo "<br>".$days3;

With an array

$days = array("Monday","Tuesday","Wednesday");
echo $days[0];
echo $days[1];
echo $days[2];

Both print the same three days, and on three days it is close to a draw. The difference shows the moment the number stops being three.

Three things separate variables cannot do

1. You cannot loop over them

This is the real one. With an array, printing three days and printing three hundred is the same four lines:

for($i=0; $i < count($days); $i++){
    echo $days[$i]."<br>";
}

With $days1, $days2, $days3 there is no way to write that loop at all. $days.$i is not a thing. You would have to type one echo per day, for ever.

2. You cannot count them

count($days) answers "how many?" even when the answer changes while the program is running. Three separate variables cannot be counted — only you know there are three, and only until you add a fourth and forget.

3. You cannot grow or shrink them

An array is dynamic, which is his word for it. You can add to it while the program runs:

$days[] = "Thursday";   // add on the end
$days[5] = "Saturday";  // add at a key you choose
unset($days[1]);        // remove one

You cannot invent a new variable while the program is running. The number of variables is fixed when you type the file.

A use case where separate variables simply fail

Count how many times each letter appears in a word. You do not know in advance which letters will turn up, so you cannot name the variables.

$word = "MISSISSIPPI";
$counts = array();

for($i=0; $i < strlen($word); $i++){
    $ch = $word[$i];
    if(isset($counts[$ch])){ $counts[$ch] = $counts[$ch] + 1; }
    else { $counts[$ch] = 1; }
}

foreach($counts as $letter => $howMany){
    echo $letter." appears ".$howMany." times\n";
}
Prints 
M appears 1 times
I appears 4 times
S appears 4 times
P appears 2 times

The keys were invented while the program ran, from the letters it found. There is no version of this with separate variables, at any length.

His definition, worth memorising

"In PHP an array is actually an ordered map, which associates each value in the array with a key."

Every array is keys and values. In an indexed array the keys happen to be 0, 1, 2 and PHP writes them for you. In an associative array you write them yourself. It is the same structure either way — that is why foreach ($a as $k => $v) works on both.

2. Writing your own

    print "Hello\n";
}

Naming them — his four rules

  • Like variable names, but with no dollar sign.
  • Start with a letter or underscore, then letters, numbers, underscores.
  • Avoid built-in function names.
  • Case does not matter — but please do not take advantage of this.

This pair is exam material. A variable is case sensitive — $Name and $name are two different variables. A function is case insensitive — MixedCase() and mixedcase() really do call the same function. I checked both.

3. Return, and arguments

function greeting() {
    return "Hello";
}
print greeting() . " Glenn\n";
print greeting() . " Sally\n";
Prints 
Hello Glenn
Hello Sally

print and return are not the same thing. print puts it on the screen. return hands it back to whoever called the function, who then decides what to do with it — which is why . " Glenn" can be joined onto this one and could not be joined onto greet().

function howdy($lang) {
    if ( $lang == 'es' ) return "Hola";
    if ( $lang == 'fr' ) return "Bonjour";
    return "Hello";
}
print howdy('es') . " Glenn\n";
print howdy('fr') . " Sally\n";
Prints 
Hola Glenn
Bonjour Sally

There is no else anywhere. return leaves the function immediately, so once one fires nothing below it runs. The last line is the default.

Optional arguments

function howdy($lang='es') { ... }
print howdy() . " Glenn\n";      // uses 'es'
print howdy('fr') . " Sally\n";

4. By value and by reference

The pair he is most likely to make you trace.

By value — the default

function double($alias) {
    $alias = $alias * 2;
    return $alias;
}
$val = 10;
$dval = double($val);
echo "Value = $val Doubled = $dval\n";
Value = 10 Doubled = 20

$val is still 10. The function doubled its own copy. The answer only got out through return.

By reference — with &

function triple(&$realthing) {
    $realthing = $realthing * 3;
}
$val = 10;
triple($val);
echo "Triple = $val\n";
Triple = 30

$val really changed, and there is no return anywhere. The & is the whole difference.

By valueBy reference

5. Variable scope

"Variable names used inside of function code do not mix with the variables outside of the function." He calls it name spacing.

Normal — isolated

function tryzap() {
    $val = 100;
}
$val = 10;
tryzap();
echo "TryZap = $val\n";
TryZap = 10

Two different variables that happen to share a name.

Global — shared

function dozap() {
    global $val;
    $val = 100;
}
$val = 10;
dozap();
echo "DoZap = $val\n";
DoZap = 100

global says "the one in here is the one out there".

He says use global rarely — "use this wisely, young Jedi" — and lists three better ways: pass it in as a parameter, pass it back as a return value, or pass it by reference.

The exception is the superglobals. $_GET, $_POST and the rest are visible inside a function with no global at all. I checked this.

6. Including files

WrittenWhat it does

The difference that matters: include carries on with a warning if the file is missing. require stops the script dead. Use require for anything the page cannot work without.

Making one

$days = array();                                  // empty
$days = array("Mon","Tue","Wed","Thu","Fri");     // with values
$days = ["Mon","Tue","Wed","Thu","Fri"];          // the short way

A trap on his slide 18. $days = array(5); does not make an array with five empty slots. It makes an array with one element, whose value is the number 5:

Array ( [0] => 5 )      count = 1

PHP arrays do not need a size. They grow as you put things in them.

Reading, adding, removing

echo $days[1];           // Tue  - square brackets, key inside
$days[5] = "Sat";        // add at a key you choose
$days[] = "Sun";         // add on the end, next free key
unset($days[1]);         // remove that one

Keys do not have to be in order

His example — note it jumps from 4 to 7:

$days = array("Mon","Tue","Wed","Thu","Fri");
$days[7] = "Sat";
print_r($days);
Prints 
Array ( [0] => Mon [1] => Tue [2] => Wed [3] => Thu [4] => Fri [7] => Sat )

There is no key 5 or 6. Asking for $days[6] gives NULL. This is why isset() matters, and why a for loop counting 0,1,2… is the wrong tool for an array whose keys have gaps.

Walking through an array

Counted loop — indexed only

$stuff = array("Tarraf","PHP");
for($i=0; $i < count($stuff); $i++) {
    echo "I=",$i," Val=",$stuff[$i],"\n";
}
I=0 Val=Tarraf
I=1 Val=PHP

foreach — works on both

$stuff = array("name" => "Tarraf",
               "course" => "PHP");
foreach($stuff as $k => $v ) {
    echo "Key=",$k," Val=",$v,"\n";
}
Key=name Val=Tarraf
Key=course Val=PHP

His point: with non-sequential or named keys you cannot write a simple $i++ loop. foreach is the tool that does not care what the keys are. Run it on an indexed array and the keys just come out as 0, 1, 2 — I checked.

Associative arrays

$stuff = array( "name" => "Rabih",

$za = array();              // or build it up one at a time

Functions · 1 — from his problem sheet

The quadratic equation

Ask the user for two coefficients and a constant, then say whether the equation has one solution, two solutions, or none.

Show the answer 
function solveQuadratic($a,$b,$c){
    if($a == 0){
        return "Not a quadratic equation (a must not be 0)";
    }
    $d = ($b*$b) - (4*$a*$c);
    if($d > 0){
        $x1 = (-$b + sqrt($d)) / (2*$a);
        $x2 = (-$b - sqrt($d)) / (2*$a);
        return "Two solutions : x1 = ".$x1." and x2 = ".$x2;
    }
    if($d == 0){
        $x = -$b / (2*$a);
        return "One solution : x = ".$x;
    }
    return "No real solution";
}
a=1 b=-5 c=6   -> Two solutions : x1 = 3 and x2 = 2
a=1 b=-4 c=4   -> One solution : x = 2
a=1 b=2  c=5   -> No real solution
a=0 b=2  c=4   -> Not a quadratic equation (a must not be 0)

Why this way. The whole question is the discriminant b² − 4ac. Work it out once into $d and the three cases fall straight out of it.

The $a == 0 check comes first, before anything else. If a is zero the formula divides by 2*$a, which is division by zero. The question does not ask for this check and most answers leave it out — which is exactly why putting it in is worth a mark.

Functions · 2 — from his problem sheet

integerPower(base, exponent)

Return baseexponent. integerPower(3,4) is 3×3×3×3. It must use a for or while to control the calculation.

Show the answer 
function integerPower($base,$exponent){
    $result = 1;
    for($i=1; $i <= $exponent; $i++){
        $result = $result * $base;
    }
    return $result;
}
integerPower(3, 4)  = 81
integerPower(2, 10) = 1024
integerPower(5, 0)  = 1
integerPower(7, 1)  = 7

Why $result starts at 1 and not 0. Starting at 0 would make every answer 0, because anything times zero is zero. 1 is the number that does nothing when you multiply — the same reason a running total starts at 0, which is the number that does nothing when you add.

It handles exponent 0 for free. The loop never runs, so $result is still 1 — which is the right answer. No special case needed, and that is worth noticing rather than writing an if for it.

Functions · 3 — from his problem sheet

Celsius and Fahrenheit

Two functions, two buttons — one each way.

Show the answer 
function Celsius($f){
    return 5.0 / 9.0 * ($f - 32);
}

function Fahrenheit($c){
    return 9.0 / 5.0 * $c + 32;
}
F 212   -> C 100
F 98.6  -> C 37
F 32    -> C 0
C 100   -> F 212
C -40   -> F -40

Why the brackets round ($f - 32) are not optional. Without them PHP does the multiply and divide first, so you would get 5/9*$f and then subtract 32 — a different answer. The brackets force the subtraction to happen first, exactly as his formula is written.

Why 5.0 and not 5. It is a habit worth keeping from his slide. In PHP division makes a float anyway, so it does not change the answer here — but in many languages 5/9 with whole numbers gives 0, and the whole thing collapses.

−40 is the one to test with. It is the single temperature where both scales read the same, so if your two functions disagree there, something is wrong with both.

Arrays · 4

Five marks in an indexed array

Put five marks in an array. Print each one with its student number, then the total, the average, and the highest — without max().

Show the answer 
$marks = array(14, 9, 18, 11, 20);
$total = 0;
$highest = $marks[0];

for($i=0; $i < count($marks); $i++){
    echo "Student ".($i+1)." scored ".$marks[$i]."\n";
    $total = $total + $marks[$i];
    if($marks[$i] > $highest){ $highest = $marks[$i]; }
}

echo "Total = ".$total."\n";
echo "Average = ".($total / count($marks))."\n";
echo "Highest = ".$highest."\n";
Student 1 scored 14
Student 2 scored 9
Student 3 scored 18
Student 4 scored 11
Student 5 scored 20
Total = 72
Average = 14.4
Highest = 20

count($marks) instead of 5. Add a sixth mark and nothing else has to change. Typing 5 works today and breaks the day the array grows.

$highest starts at $marks[0], not 0. Starting at 0 happens to work here, but it is wrong the moment the marks can be negative — nothing would ever beat 0. Assume the first one wins, then let the others challenge it.

($i+1) for the student number. The array counts from 0, people count from 1. That +1 is the join between the two.

Total and highest are updated inside the loop; the average is worked out after it. Dividing inside the loop would give you the average of however much you had read so far.

Arrays · 5

Prices in an associative array

Items and their prices. Print each, then the total, the number of items, and the name of the most expensive one.

Show the answer 
$prices = array("Pen" => 3, "Book" => 12, "Bag" => 25, "Ruler" => 2);
$total = 0;
$dearest = "";
$dearestPrice = 0;

foreach($prices as $item => $price){
    echo $item." costs ".$price."\n";
    $total = $total + $price;
    if($price > $dearestPrice){
        $dearestPrice = $price;
        $dearest = $item;
    }
}

echo "Total = ".$total."\n";
echo "Most expensive = ".$dearest." at ".$dearestPrice."\n";
echo "How many items = ".count($prices)."\n";
Pen costs 3
Book costs 12
Bag costs 25
Ruler costs 2
Total = 42
Most expensive = Bag at 25
How many items = 4

Why foreach and not for. The keys here are "Pen", "Book", "Bag" — there is no $prices[0] to count towards. A for loop has nothing to count. This is his exact point about needing an iterator.

Two variables for the dearest, not one. You need the price to compare against and the name to print, so you keep both and update both together. Update one without the other and you get the right price next to the wrong name.

The if is inside the loop, the printing is after. You cannot name the most expensive item until you have seen the last one.

Arrays · 6

A shopping cart — an array of arrays

Each line has a title, a price and a quantity. Print each line with its line total, then the grand total.

Show the answer 
$cart = array();
$cart[] = array("title" => "Notebook", "price" => 4,  "qty" => 3);
$cart[] = array("title" => "Pencil",   "price" => 1,  "qty" => 10);
$cart[] = array("title" => "Backpack", "price" => 25, "qty" => 1);

$grand = 0;
foreach($cart as $line){
    $lineTotal = $line["price"] * $line["qty"];
    echo $line["title"]." : ".$line["qty"]." x ".$line["price"]." = ".$lineTotal."\n";
    $grand = $grand + $lineTotal;
}
echo "Grand total = ".$grand."\n";
Notebook : 3 x 4 = 12
Pencil : 10 x 1 = 10
Backpack : 1 x 25 = 25
Grand total = 47

Two levels, so two kinds of key. The outer array is indexed — $cart[0], $cart[1] — because the lines have no natural names. Each inner array is associative, because "price" says far more than [1] ever would. Picking the right one at each level is the skill this question tests.

foreach($cart as $line) with no => $k. When you do not need the key, leave it out. Here the line number is not used, so asking for it would be noise.

$lineTotal is worked out once and then used twice — printed, and added to the grand total. Writing $line["price"] * $line["qty"] twice would work and is the kind of small repetition that becomes a wrong answer when one of the two gets edited.

Arrays · 7

Count the letters in a word

Read a word and say how many times each letter appears. You do not know in advance which letters there will be.

Show the answer 
$word = "MISSISSIPPI";
$counts = array();

for($i=0; $i < strlen($word); $i++){
    $ch = $word[$i];
    if(isset($counts[$ch])){
        $counts[$ch] = $counts[$ch] + 1;
    } else {
        $counts[$ch] = 1;
    }
}

foreach($counts as $letter => $howMany){
    echo $letter." appears ".$howMany." times\n";
}
M appears 1 times
I appears 4 times
S appears 4 times
P appears 2 times

This is the question that proves why arrays exist. The keys are invented while the program runs, out of whatever letters it finds. There is no way to write this with separate variables at all — you would have to know the letters before you started.

The isset is the whole trick. First time a letter turns up there is no counter for it yet, so you create it at 1. Every time after, you add one to what is there. Without the isset you would be adding 1 to a key that does not exist, which is a warning on the page.

Two loops, and they are different kinds. The first walks the word by position, so it is a for. The second walks the array, whose keys are letters, so it has to be a foreach.

The GPA calculator

A student takes three subjects — PHP, Data Science and English — and sits three tests in each. Nine boxes on a form.

Work out the average of the three tests for each subject, give each subject a letter grade, then the GPA, which is the average of the three subject averages. Use a function.

Show the answer

One function, called four times. That is the whole reason this question exists. average3() does not know or care whether it is averaging three tests or three subject averages — it averages three numbers. So the GPA line is the same function again:

$gpa = average3($phpAvg,$dsAvg,$enAvg);

Written without a function you would type the same (a+b+c)/3 four times, and the pass mark problem from Why functions? is waiting for you.

letterGrade() is called four times too — once per subject and once for the GPA. A function that takes a mark rather than a subject is what makes that possible. Had it been written as phpGrade() it would have been useless for the other three.

Why the two checks are separate. is_numeric first, then the 0–100 range, as two branches with two different messages. One combined check would be able to say only "something is wrong".

number_format($x, 2) for the display only. The rounding happens when the number is printed, never before. Round $phpAvg itself and that rounding error goes into the GPA.

A thing worth knowing about averaging averages. Here the GPA comes out the same whether you average the three subject averages or all nine tests at once — I checked, both give exactly 82.00.

That is only true because every subject has the same number of tests. With 2 tests in one subject and 4 in another, averaging the averages gives 50 where averaging all six marks gives 33.33. Different answers to different questions. This question says "the average of the three subject averages", so that is what the code does.

Where arrays would come in. Nine variables named $php1 … $en3 is exactly the smell from Why arrays?. With an array of subjects, each holding an array of three marks, the nine reads and the nine checks become two small loops, and adding a fourth subject becomes one line instead of a rewrite. Try it that way once you have this version working — it is practice question P12.

Practice

No answers here on purpose. Work on paper or in VS Code, then run it under XAMPP and see whether it does what you expected.

Functions

P1 · warm-up

A function that says hello to somebody

Write greetPerson($name) that returns "Hello Fatima" when you pass it "Fatima". Call it three times with three different names.

Then change it so that calling greetPerson() with nothing says "Hello guest".

P2

Biggest of three, as a function

Write biggestOfThree($a,$b,$c) that returns the largest. No max(). Then write smallestOfThree beside it.

Test it with the biggest number first, then last, then with all three the same.

P3

By value or by reference?

Say what each prints, before you run it. Then run it.

function addTen($n){ $n = $n + 10; return $n; }
function addTwenty(&$n){ $n = $n + 20; }

$score = 5;
$other = addTen($score);
echo "A: ".$score." ".$other."\n";

addTwenty($score);
echo "B: ".$score."\n";
P4

Two files and include

Put biggestOfThree and smallestOfThree in a file called maths.php with nothing else in it. Make page.php with a form of three boxes and two buttons, and include "maths.php"; at the top.

Then rename maths.php and reload. Note what the error says. Change include to require and reload again — the difference is the point of the exercise.

Arrays

P5 · warm-up

Seven days

Put the seven days in an indexed array. Print them with a for loop, numbered 1 to 7. Then print just $days[3] and check it is the day you expected.

If it isn't, you have found the thing arrays catch everybody with once.

P6

A phone book

Make an associative array of five names and phone numbers. Print them all with foreach. Then ask for one name and print just that number, or "Not found" if it is not in there.

isset() is what decides between the two.

P7

Pass and fail, counted

An array of eight marks out of 20. Print each one with PASS or FAIL beside it — the pass mark is 10 — then how many passed and how many failed.

Two counters, both set to 0 before the loop. If you set them inside it, they reset every time round.

P8

A class register — array of arrays

Five students, each with a name, a mark and a city. Print a table with one row per student, then the average mark, then the name of the student with the highest mark.

Outer array indexed, inner arrays associative. The heading row of the table goes outside the loop — inside, you get five of them.

P9

Counting words

Take a sentence. Use explode(' ', $sentence) to cut it into an array. Print how many words there are, then the longest word.

Longest means strlen() — and the same "assume the first one wins" pattern as the biggest number.

P10 · the two lessons together

A marks report, properly split

Write letterGrade($mark) and average($marks) — note the second one takes the whole array as its argument. Put both in grades.php.

Then a page that holds an array of six marks, includes grades.php, and prints a table of mark and letter grade, with the class average underneath.

This is the shape of almost any question he can set from these two lessons: an array holding the data, a function holding the rule, a loop joining them.

P12 · the GPA calculator, rebuilt

Nine variables become two loops

Take solved question 8 and write it again with arrays. Hold the subjects in one array, each with its three marks:

$subjects = array(
    "PHP"          => array(88, 92, 79),
    "Data Science" => array(65, 71, 58),
    "English"      => array(95, 100, 90)
);

Print the same table and the same GPA. Then add a fourth subject and count how many lines you had to change.

Write averageOf($marks) taking the whole array instead of three separate numbers, and it will work for a subject with four tests too. A foreach over the subjects, a running total for the GPA.

Trace these — no computer

P11

What does each one print?

$a = array("x","y","z");
$a[5] = "w";
echo count($a);
$b = array("p" => 1, "q" => 2);
foreach($b as $k => $v){ echo $k.$v; }
function f($x){ $x[] = 99; return count($x); }
$c = array(1,2,3);
echo f($c)." ".count($c);

The third one is by value and by reference wearing a disguise. Arrays follow the same rule as numbers.
